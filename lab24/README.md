# Лабораторна робота №24 — Strategy + Observer: динамічна підстановка алгоритмів + тести

## Тема та мета

**Тема:** Strategy + Observer — динамічна підстановка алгоритмів + тести.

**Мета:** застосувати патерни Strategy та Observer для гнучкої системи, яка дозволяє динамічно змінювати алгоритми обробки даних та автоматично сповіщати залежні компоненти про зміни, а також написати юніт-тести для перевірки функціональності.

## Патерн Strategy

Дозволяє змінювати алгоритм обробки числа під час виконання.

- **`INumericOperationStrategy`** — інтерфейс з методом `double Execute(double value)`.
- Реалізації:
  - `SquareOperationStrategy` — квадрат числа;
  - `CubeOperationStrategy` — куб числа;
  - `SquareRootOperationStrategy` — квадратний корінь (кидає виняток для від'ємних).
- **`NumericProcessor`** — контекст: приймає стратегію через конструктор, має `SetStrategy(...)` для зміни під час виконання і `Process(input)`, що делегує обробку поточній стратегії.

## Патерн Observer (через події C#)

Дозволяє автоматично сповіщати кілька компонентів про новий результат.

- **`ResultPublisher`** (Subject) — має подію `event Action<double, string> ResultCalculated` (результат, назва операції) і метод `PublishResult(result, operationName)`, який її викликає.
- Спостерігачі (підписуються на подію):
  - `ConsoleLoggerObserver` — виводить результат і назву операції в консоль;
  - `HistoryLoggerObserver` — накопичує історію результатів у `List<string>`;
  - `ThresholdNotifierObserver` — сповіщає, якщо результат перевищив поріг.

## Тести

`SimpleTests` — легкі юніт-тести без зовнішнього фреймворку (щоб запускалися будь-де, зокрема онлайн). Перевіряють:
- коректність кожної стратегії (`Square`, `Cube`, `Sqrt`);
- роботу `NumericProcessor` та зміну стратегії через `SetStrategy`;
- виняток `Sqrt(-1)`;
- доставку результату й назви операції через подію;
- накопичення історії спостерігачем.

Ці ж перевірки в «промисловому» проєкті оформлюються як `[Fact]`-методи xUnit в окремому тест-проєкті.

### Файли

- `INumericOperationStrategy.cs`, `Strategies.cs`, `NumericProcessor.cs` — патерн Strategy.
- `ResultPublisher.cs`, `Observers.cs` — патерн Observer.
- `SimpleTests.cs` — юніт-тести.
- `Program.cs` — демонстрація в `Main`.

## Висновки

Strategy відокремив алгоритми обробки від контексту — `NumericProcessor` не знає, що саме рахує, і алгоритм підмінюється на льоту. Observer через події C# розв'язав видавця й підписників: `ResultPublisher` не знає, хто слухає, а спостерігачі додаються/прибираються незалежно. Разом патерни дають гнучку, слабозв'язану систему, а юніт-тести підтверджують коректність кожного компонента.
